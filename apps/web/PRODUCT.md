# Product

## Platform

web

## Users

- 管理员：维护用户、角色、模型密钥、平台规则、系统配置和审计记录。
- 运营：维护 SKU、素材、模板、生成任务、批量作业和导出批次。
- 设计：维护品牌视觉包、执行单图编辑并处理驳回结果。
- 审核：查看自动质检证据并通过或驳回图片，不能读取或修改模型密钥。

## Product Purpose

AI 生图中台把商品素材转换为国内外主流电商平台可用的主图、辅图、场景图、详情图和服装鞋帽专项图片。成功意味着生产过程可批量执行、失败可隔离恢复、结果可人工审核，且每张图片都能追溯到 SKU、参考素材、规则版本、模型参数、成本和审核人。

## Positioning

系统以商品真实性锚点、三层模板规则、不可变资产版本和人工审核门槛约束模型输出；它不是通用生图社区，也不是 ComfyUI 换皮。

## Operating Context

运营人员在桌面后台创建或导入 SKU，上传并分类商品参考图，维护真实性锚点，选择平台、品类、品牌模板和授权模特，调整套图计划后批量执行。结果经过自动质检与人工审核；不合格单图可以重试、复制参数重做或进入不可变编辑分支，合格结果按平台规则导出。

## Capabilities and Constraints

- 覆盖淘宝/天猫、京东、拼多多、抖音电商、Amazon、TikTok Shop、Shopify、Temu、Shopee、Lazada 和 eBay 的版本化默认规则包。
- 支持系统虚拟模特、品牌授权模特、多视角参考、商品图、多角度和虚拟试穿任务编排。
- 默认严格商品模式；缺少真实侧面或背面参考时阻止相应正式输出。创意补全必须明确标记并人工审核。
- 支持可配置模型 API Key、通用 HTTP 和 ComfyUI 执行适配器；API Key 仅以服务端密文保存。
- 支持局部编辑、画布变换、确定性文字与 Logo 图层、版本分支、审核和可追溯 ZIP 导出。
- PostgreSQL 是任务权威状态，Redis 只负责唤醒提示，MinIO/S3 保存内容寻址的不可变资产。
- 首版不包含 Photoshop 级编辑、基础模型训练、自动发布商品、完整 ERP/PIM/DAM 替代或公众作品社区。
- 真实模型质量、30 SKU 基准、平台规则有效性、GPU 性能和真实账单属于发布验收，不得由 Mock 流程推断。

## Brand Commitments

- 产品名称使用“AI 生图中台”。
- 界面语言以简洁、直接、可审计的中文运营文案为主，Provider、SKU、API 等行业术语保留英文。
- 现有深色高密度运营后台是既有视觉权威；扩展页面保持同一导航、面板、表单、状态和数据表格语言。

## Product Principles

1. 商品真实性优先于生成速度和创意完整度。
2. 每次模型调用、人工修改、规则选择和导出都必须可追溯。
3. 批量生产允许部分失败，但不能让失败行破坏成功行。
4. 自动化负责提效，人工审核负责最终放行。
5. 运营人员操作业务对象和明确参数，不需要理解底层节点图。

## Accessibility & Inclusion

后台必须支持键盘操作、可见焦点、语义化表单标签、清晰的错误恢复路径、减少动态效果，并在 375px 手机、横屏和桌面宽度保持内容可读且不产生页面级横向溢出。
