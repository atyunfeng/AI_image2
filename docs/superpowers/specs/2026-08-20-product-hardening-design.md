# AI 生图中台生产化收口设计

## 目标

在不改变既有商品真值、模板、不可变资产和人工审核边界的前提下，把 M6 从本地功能型 MVP 收口为可部署、可扩容、可观测、可真实验收的版本。

## 范围

1. 四类角色必须能够独立完成其职责，权限不足和服务异常不能伪装成空数据。
2. 模型配置支持新增、修改、启停、密钥轮换、连接测试和审计；Provider 适配器继续由统一能力契约隔离。
3. 30 SKU Benchmark 必须真实调用中台任务流程，输出逐次 JSONL 和汇总报告；没有真实素材或 Provider 时明确失败，不生成示例结果。
4. Worker 实现进程内并发、自动重试、退避、租约恢复和队列去重；PostgreSQL 仍是事实源。
5. 列表与运营统计支持有界查询，批量导入从请求线程移出，资产交付避免不必要的全量内存复制。
6. 深度健康检查覆盖数据库、Redis、对象存储和 Worker 心跳；界面只根据真实结果展示系统状态。
7. 平台规则版本增加来源、适用区域、生效及复核信息；默认规则仍明确标记为非官方认证。
8. 补齐登录限流、生产密钥校验、安全响应头、Provider 出站保护、非 root 容器和备份恢复入口。
9. 保持现有深色高密度运营后台风格，修复移动导航、键盘操作、表单标签、错误恢复和退出登录。

## 非目标与外部验收

- 不实现自动上架。
- 不伪造真实模型质量、平台官方认证、真实成本或 30 SKU 通过结果。
- 不内置用户未授权的人像或商品素材。
- 真实 Provider、真实 SKU、生产域名、KMS 和对象存储由部署环境提供；代码必须在缺失时给出明确阻断信息。

## 架构决策

### 权限与查询

新增审核队列只读接口，允许管理员、运营和审核员读取审核所需的最小批次信息。前端导航与接口角色矩阵保持一致。服务端 API 客户端返回可区分的未授权、无权限、暂不可用和空数据状态。

### 模型注册与 Provider

模型配置使用 PATCH 完成非密钥字段更新、启停和可选密钥轮换，密钥继续使用 AES-GCM 密文保存。每次创建、更新、测试和启停写入脱敏审计。Provider URL 只允许 HTTP(S)，生产环境默认阻止回环、链路本地和私网地址，ComfyUI 私网访问通过显式配置放行。

### Benchmark 与质量

Benchmark Runner 读取清单、上传或复用商品与参考素材、创建任务、轮询终态并写入 JSONL。报告包含成功率、技术规则通过率、人工试穿通过率和分品类结果；人工字段缺失时显示“未完成”，不能判定正式通过。自动质检增加可插拔语义检查结果结构，默认实现只报告未配置，不冒充通过。

### Worker 与任务可靠性

Worker 使用固定上限的 asyncio 任务集合并发消费。可重试错误进入 `retry_queued`，记录下一次执行时间并指数退避；超过上限进入失败终态。恢复扫描只发布到期且未被有效租约占用的任务，Redis 使用带 TTL 的去重键。Worker 定期刷新心跳。

### 性能与运维

产品、批次、批量作业和编辑项目采用有界分页。批次最新 Step 用子查询一次加载，运营统计下推数据库。批量导入先持久化作业，再由后台处理。健康检查分 liveness/readiness；备份脚本覆盖 PostgreSQL 与 S3/MinIO 清单。

### 前端

移动端使用可展开导航而非截断的横向列表；当前页面和权限可见。全局错误页提供重试或重新登录。审核表单具备显式标签和动态状态播报；画布保留指针操作，同时提供自动选择和可聚焦的替代说明。顶部状态来自 readiness，不再固定显示在线。

## 验收标准

- 纯 reviewer 用户能看到、打开、通过和驳回待审核批次，不能访问模型密钥或用户治理。
- 模型更新、启停和密钥轮换均有脱敏审计，旧密钥不会通过 API 返回。
- Benchmark `run` 不再是固定异常；无外部条件时给出确定性阻断，有条件时产生真实 JSONL。
- 单 Worker 能按配置并发执行；瞬时 Provider 错误自动退避重试，超过上限失败。
- 所有列表默认有界，页面能翻页；API/权限错误不会显示成空数据。
- readiness 任一依赖失败时返回非 2xx，并在界面准确显示。
- 后端测试、前端测试、lint、类型检查、构建、Compose、Playwright 和 375/1440 截图检查通过。
