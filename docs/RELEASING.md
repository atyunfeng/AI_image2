# 发布流程

维护者发布版本时应执行以下检查：

1. 确认 `main` 工作区干净，CI、后端测试、前端测试和构建均通过。
2. 对完整 Git 历史运行敏感信息扫描，确认没有有效凭据或未授权素材。
3. 按锁文件复核依赖许可证，并更新 `THIRD_PARTY.md`。
4. 更新版本号和发布说明，明确模拟验证与真实模型验收的区别。
5. 创建签名或受保护的版本标签，例如 `v0.1.0`。
6. 使用该标签生成源码归档和校验值，保证归档包含许可证、构建脚本及锁文件。
7. 若分发容器或其他目标代码，同时提供或书面指向完全对应的源码。
8. 在 GitHub Release 中记录已知限制、升级步骤和安全修复信息。

发布包不得包含 `.env`、真实 Provider Key、数据库备份、用户上传内容或内部测试数据。
